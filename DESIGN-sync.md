# Ariadne: аккаунт и избирательная синхронизация (фаза C) — дизайн

Исходные решения — на доске «Ariadne» (блоки-решения от 07.11.2026).
Кратко здесь: один аккаунт (логин+пароль), сервер A /srv/ariadne:3010
(Tailscale), синхронизируется только явно помеченное совместным,
конфликты — «новее победил» (LWW).

## Модель совместности

- Единица шеринга **доска** или **заметка (.md)**.
- Правый клик → «Сделать совместной» → подтверждение → необратимо.
- Доски: `boards.shared_at` (миграция). Заметки: `.ariadne/shared.json`
  (список имён) — заметки остаются плоскими .md в Sessions\.
- Папки/группы/закрепления — личные настройки каждого ПК, не синхронятся.
- Удаление совместного — у всех (tombstone расходится). Переименование
  заметки = удаление старого имени + появление нового, синхронизируется само.
- Вложения досок и ассеты заметок (_assets/<заметка>/) синхронизируются
  вместе с владельцем.

## Сервер (тот же ariadne-server.js, порт 3010)

Хранилище: SQLite (`node:sqlite`, без зависимостей) `data/sync.db` + блобы
`data/blobs/<sha256>` (дедупликация по содержимому).

Таблицы:
- `account(login, pwhash, salt)` — ровно одна строка.
- `tokens(token, created_at)`.
- `boards(id, row_json, version, deleted, rev)` — row_json = строка boards;
  version = updated_at клиента (LWW: входящее побеждает при version >).
  Зависимые строки доски — в `board_rows(board_id, kind, id, row_json,
  version, deleted, rev)`, kind: blocks | links | tags | block_tags |
  comments | checklist_items | attachments. version = updated_at ?? 
  created_at ?? 0; для строк без времён (tags, block_tags) version = 0 и
  сравнение по содержимому (json-хэшу): различается — побеждает пуш.
- `files(path, sha256, size, deleted, rev)` — заметки .md и ассеты.
- `meta(key, value)` — счётчик rev.

API (всё с токеном, кроме auth/register):
- `POST /register {login, password}` — 409 если аккаунт уже есть (открыт,
  пока аккаунта нет; далее только tailnet).
- `POST /auth {login, password}` → `{token}`.
- `GET /sync/state` → `{rev, boards: [{board, rows[]}], files[]}` — всё
  состояние (объёмы малы, полная выдача проще дельт).
- `POST /sync/boards {boards: [{board, rows[]}]}` — сервер применяет LWW
  по каждой строке, возвращает `{rev}`.
- `POST /sync/files {files: [{path, sha256, size, deleted}]}` → `{rev}`.
- `PUT /blob/<sha256>` (тело — байты), `GET /blob/<sha256>`.

## Клиент (main-процесс, src/main/sync)

`runSync()` — полный цикл (полное сравнение, объёмы малы):
1. Тащим `GET /sync/state`.
2. Доски: объединение множеств id. Нет локально и не удалено на сервере —
   вставляем (прямой SQL + reindexBlock + touchBoard). Есть везде — построчно
   LWW (локальная version против серверной; deleted_at новее alive —
   побеждает). Итог отправляем `POST /sync/boards`.
3. Файлы: по каждой заметке/ассету sha256; разные — грузим/скачиваем блоб,
   LWW по mtime (расхождение часов фиксируем в отчёте синка). Блобы досок —
   то же.
4. Прогресс и результат — событием в рендерер (тост + статус в настройках).

Триггеры: старт (после проверки обновлений), каждые 10 минут, кнопка
«Синхронизировать» в настройках. Свойства: идемпотентность (повторный запуск
без изменений ничего не меняет).

## UI

- Сайдбар досок: контекст-меню «Сделать совместной…» (подтверждение),
  у совместных — иконка Users и мягкая подсветка.
- Сайдбар заметок: то же для .md, иконка на строке.
- Настройки → «Аккаунт и синхронизация»: адрес сервера (по умолчанию
  http://100.68.27.113:3010), логин/пароль, «Войти», «Синхронизировать
  сейчас», время последней синхронизации.
- Тосты: «Синхронизировано: 2 доски, 3 заметки» / ошибки канала.

## Границы v1 (зафиксировано)

- Не «одновременное редактирование», а LWW по строке.
- Часы ПК могут разойтись — при равенстве/споре побеждает серверное время
  приёма; конфликт содержимого заметок решается mtime.
- Один аккаунт: «поделиться» = передать логин/пароль. Разрешение конфликтов
  между участниками — LWW.
